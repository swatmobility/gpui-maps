gpui-maps is a vector-map engine written in Rust. It draws on your GPU, inside your GPUI window, and the same code runs on iOS and in the browser as WebAssembly. No web view, no JavaScript, no access token.

Your app also needs GPUI and Tokio. See the commands.

Your first map in a few commands.

Run the first example from the repository, or add a map to your own GPUI app. Both open a window on Singapore with an open, keyless basemap.

Try an example

zsh
$ git clone https://github.com/swatmobility/gpui-maps
$ cd gpui-maps
$ cargo run --release --example hello_map
   Compiling gpui-maps v0.8.0
    Finished `release` profile [optimized]
     Running `target/release/examples/hello_map`

Add to your app

zsh
$ cargo new my-map && cd my-map
$ cargo add gpui-maps
$ cargo add gpui-pre@=0.3.12 --rename gpui
$ cargo add gpui-pre-platform@=0.3.12 \
    --rename gpui-platform -F font-kit
$ cargo add tokio -F rt-multi-thread
# put the code below in src/main.rs
$ cargo run --release
src/main.rs
use gpui::{prelude::*, px, size, App, Bounds, WindowBounds, WindowOptions};
use gpui_maps::basemaps::{self, Basemap};
use gpui_maps::map_view::MapView;

fn main() {
    let runtime = tokio::runtime::Runtime::new().expect("tokio runtime");
    let rt = runtime.handle().clone();
    gpui_platform::application().run(move |cx: &mut App| {
        let bounds = Bounds::centered(None, size(px(1024.0), px(768.0)), cx);
        let options = WindowOptions { window_bounds: Some(WindowBounds::Windowed(bounds)), ..Default::default() };
        cx.open_window(options, move |_window, cx| {
            let b = basemaps::load(Basemap::Liberty).expect("the bundled Liberty style compiles");
            // Singapore, zoom 12; the view resizes itself to the window.
            let map = cx.new(|_| MapView::new(103.85, 1.29, 12.0, 1024.0, 768.0, b.style, b.source, rt.clone()));
            if let Some(sprite) = b.sprite {
                basemaps::spawn_sprites(map.downgrade(), sprite, None, rt, cx);
            }
            map
        })
        .expect("open the window");
    });
    std::mem::forget(runtime); // the app owns the process from here
}

A map is a GPUI view, so you add it to a window like any other element. The getting-started guide goes on to styles, your own data and offline maps.

Everything a map needs, in one engine.

The live maps above use a few of these. The rest are in the examples and the docs.

Tiles
Vector tiles over HTTP, PMTiles, MBTiles and raster tiles. Runs fully offline from a single .pmtiles file, with no account, key or outside service, so it works on private networks with no internet.
Data
GeoJSON, CSV, FlatGeobuf, GeoParquet and Cloud-Optimised GeoTIFF, with hover and click picking.
Visualisation
Arcs, animated trips, heatmaps, hexagon and grid binning, dot density, clustering.
3D
A globe with atmosphere and sky, building extrusion, and glTF models.
Navigation
Turn-by-turn route following on Ferrostar's Rust core: manoeuvres, rerouting and a follow camera, drawn by the engine.
Capture
Render a camera or a scripted map story to PNG or video, with no window.
Big data
Dot-density and H3 hexagon layers that stream their tiles live from ClickHouse, read-only and behind a SQL guard.
Dashboards
Charts linked to the map, defined in one JSON file with the SQL inline, for ClickHouse and Postgres (swat-maps-dash).
Catalogues
STAC 1.1 catalogues of open geodata, read into map layers with their licences (swat-maps-stac).

Your coding agent can drive the map.

An app built on gpui-maps can open a local HTTP port that describes itself. An agent lists the actions, calls them, and reads the map's state back as JSON, so it can move, inspect and test the map without screenshots.

claude
$ GPUI_MAP_AGENTIC_PORT=7334 cargo run --release --example basic_map &
$ claude
 
> Fly to Tokyo Station and tilt it so the buildings show.
 
● Bash(curl -s localhost:7334/ | jq -c '[.actions[].name]')
  ⎿ ["map.state","map.tiles","map.layers",…,"map.fly_to",…]
 
● Bash(curl -s -X POST localhost:7334/map/fly_to \
       -d '{"lon":139.7671,"lat":35.6812,"zoom":16,"pitch":60,"ms":1500}')
  ⎿ {"ok":true,"camera":{"lon":139.7671,"lat":35.6812,"zoom":16.0,
     "pitch_degrees":60.0,"bearing_degrees":null},"eased_ms":1500.0}
 
● The map is over Tokyo Station at zoom 16, tilted 60° so the
  buildings stand up. Read map.state to confirm what it drew.
  • Self-describing. GET / returns every action with its method, path and parameters, so the agent never works from a stale list.
  • Local only. The port binds to 127.0.0.1 and is off unless your app turns it on.
  • Reusable. The gpui-agentic-http crate gives any GPUI app the same surface, with an MCP server and a skill for Claude Code.

Connect Claude Code.

Start your app with its agentic port open, then pick either way, or both. They also work for any other GPUI app built on gpui-agentic-http.

MCP server
$ cargo install gpui-agentic-http
$ claude mcp add gpui-maps -e AGENTIC_HTTP_PORT=7334 \
    -- agentic_mcp_server

Every action becomes a Claude Code tool. A new action shows up as a tool by itself.

Skill
$ mkdir -p .claude/skills
$ cp -r gpui-agentic-http/skills/agentic-app \
    .claude/skills/

Claude Code finds the app's port and calls its actions over HTTP. Nothing to configure.

Rust everywhere: desktop, mobile and WebAssembly.

One engine, written once in Rust with WGSL shaders. It compiles to a native macOS view, an iOS app and a WebAssembly module, and draws the same map on each.
